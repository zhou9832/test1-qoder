纯 Markdown 文档目录（无代码与构建产物），按职责划分为两类资产：
- 顶层规范文件：`prd.md`（需求规格基线，定义 Project/Task/Tag/TimeLog 实体关系、状态机、API 端点清单、数据字典、前端页面清单及 V1-V6 验收标准）、`defect-ledger.md`（D01-D20+ 缺陷追踪账本，记录现象、类型、影响、期望兜底机制与 v0→v3 修复状态）、`decisions.md`（架构决策总表）、`rule-audit.md` / `agent-audit.md` / `skill-audit.md` / `wiki-rule-audit.md`（规则/智能体/技能/Wiki 审计）、`adr-formalization-report.md` / `quality-loop-report.md` / `v3-acceptance-report.md`（各阶段验收与质量闭环报告）。
- `architecture/` 子目录：`domain-model.md`（领域模型详述）、`api-contract-v1.yaml`（OpenAPI 风格的 API 契约）、`decisions-index.md`（ADR 索引与模板，含 ADR-001~005 分别覆盖 H2 内存库、契约优先、zod 运行时校验、transitions 动作端点、Hook 隔离测试）。
依赖方向单向向外：文档通过相对路径交叉引用仓库内其他工程资产（如 `docs/architecture/domain-model.md`、`docs/architecture/api-contract-v1.yaml`），不反向依赖源码；`principle.md` 等外部文档在缺陷报告中被对照验证分层、响应格式、异常处理、命名、时间类型、校验、构建等维度。
