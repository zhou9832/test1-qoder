# API 契约同步技能

后端契约变更时，严格按此顺序同步，任何一步失败则停下报告，不要跳过。
本技能执行 .qoder/rules/30-api-contract.md 定义的流程，规则内容以该文件为准。

## 步骤（顺序不可颠倒，每步必须有完成标志）

1. **列引用点**：搜索并输出对照表——后端该字段的 Java 定义与所有使用处、
   契约文件中的 schema 定义、web/src/api/schema.d.ts 生成结果、
   前端组件中的取值处。此表输出后【停下等用户确认】，这是 30 号规则的强制停止点。
   ✅ 完成标志: 输出完整的对照表 + "现在请您确认，确认后我将继续步骤 2"
   
2. **改后端**：按确认的方案修改 DTO/Entity/契约注解。
   ✅ 完成标志: 列出修改的文件路径 + @JsonProperty/@JsonAlias 等注解变更
   
3. **导出契约**：运行 gradle 任务导出 openapi.yaml。
   ✅ 完成标志: 终端输出"Success"或成功消息 + openapi.yaml 文件时间更新
   
4. **生成类型**：运行 scripts/generate-api-types.mjs（或 pnpm gen:api）。
   ✅ 完成标志: 终端输出成功消息 + schema.d.ts 文件大小变化
   
5. **改前端消费**：修正因类型变化而报错的组件引用。
   ✅ 完成标志: 列出修改的组件文件名 + TypeScript 编译错误是否减少
   
6. **验证**：pnpm typecheck 必须通过——这是跨端一致性的物理门禁，
   不通过不得声称完成。
   ✅ 完成标志: `pnpm exec tsc --noEmit` 输出零错误或显示"Found X errors"

## 完成标准
- typecheck 零错误；
- 契约、生成类型、前端消费三者字段完全一致；
- 输出"变更影响表"：改了哪些文件、每个文件的变化点。
