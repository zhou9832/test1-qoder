# 架构决策记录 (ADR)

## ADR-001: 引入 Zod 作为前端运行时类型校验库

### 1. 变更说明与依赖自证 (Charter 规则 3 审查)
- **新增依赖**：`zod` (npm package)
- **为什么必需 (必要性论证)**：
  1. **解决痛点**：TypeScript 编译期的类型会在打包发布后“蒸发”，无法防范线上后端 API 数据格式不一致或字段缺失导致的静默白屏。
  2. **契约守门**：在“指定文件生效 (`glob`)”的前端规则中，强制要求在 API 响应入口层使用 Zod 进行 Schema 校验；一旦校验失败直接触发 `PageState` 的 Error 态，阻止非法数据污染组件。
  3. **替代方案评估**：若不引入 Zod，需手写大量 `if-else` 或 `typeof` 类型判断代码，不仅冗余且极易遗漏，违背“交付极简”原则。

### 2. 决策与裁决结论
- **裁决结果**：**通过 (Approved)**。
- **作用范围**：仅限 `web/src/api/client.ts` 及前端数据入口校验，不得引入额外重型校验框架。
