## 3. 假设检验（Statistical Testing Lite）

> **说明**: 由于每组仅 n=1，无法做传统的 t-test/ANOVA。改用**效应量（Effect Size）**评估改进幅度。

### H1: B 组比 A 组一次通过率高

```
Hypothesis: H1: P_1pass_B > P_1pass_A
Alternative (H0): P_1pass_B ≤ P_1pass_A

Effect Size (Cohen's h):
h = 2 × arcsin(√P_1pass_B) - 2 × arcsin(√P_1pass_A)
  = 2 × arcsin(√____) - 2 × arcsin(√____)
  = ____ （正数表示 B > A）

结论: 
- h > 0.2 → 小效应（B 略有改善）
- h > 0.5 → 中效应（B 明显改善）
- h > 0.8 → 大效应（B 大幅改善）
- h < 0   → H1 不成立，B 不如 A
```

## 4. 异常值诊断（Anomaly Detection）

### 4.1 Z-Score 检测法（基于三组均值和标准差）

```

X_A = ____, X_B = ____, X_C = ____
Mean_Mu = (X_A + X_B + X_C) / 3 = ____
Std_Sigma = √(((X_A-Mu)² + (X_B-Mu)² + (X_C-Mu)²) / 3) = ____

Z_X = (X - Mu) / Sigma

Z_A = (____ - ____) / ____ = ____
Z_B = (____ - ____) / ____ = ____
Z_C = (____ - ____) / ____ = ____

判定规则:
- |Z| > 2 → 异常值（需要调查原因）
- |Z| < 1 → 正常分布
```

### 4.2 常见异常模式

| 异常模式 | 表现 | 可能原因 | 处理方式 |
|---------|------|---------|---------|
| 组间污染 | B 或 C 的数据接近 A | 降级操作不干净，rules/skills 未完全移除 | 标注但不剔除（仍是真实世界的一种场景） |
| 会话卡死 | 某组 Credits > 5000 | AI 陷入重试循环、Prompt 太模糊 | 保留并记录（这本身就是规范价值的证据） |
| 零缺陷奇迹 | 某组一次通过率=1 且所有缺陷=0 | 任务太简单或未仔细审查 git diff | 核实后保留，标注"任务复杂度不足" |
| 倒退现象 | B 比 A 差或 C 比 B 差 | 规则冲突/上下文超载 | 研究规则集是否有矛盾条款 |

## 5. 从数据到推广：决策框架

### 5.1 四象限分析法

```
坐标轴定义:
X 轴 = 一次通过率（质量指标）
Y 轴 = Credits 消耗（成本指标）

四象限:
┌──────────────────┬──────────────────┐
│   右上象限       │   左上象限       │
│  高质量·高成本   │  高质量·低成本 ← 理想区 │
│  (B 或 C 可能落此)│               │
├──────────────────┼──────────────────┤
│   右下象限       │   左下象限       │
│  低质量·高成本 ← 最差区 │  低质量·低成本   │
│  (A 通常落此)     │               │
└──────────────────┴──────────────────┘
```

**你的三组落点**:
- A 组: 质量 = ____%, 成本 = _____credits → 落于___象限
- B 组: 质量 = ____%, 成本 = _____credits → 落于___象限
- C 组: 质量 = ____%, 成本 = _____credits → 落于___象限

### 5.2 推广决策树（Decision Tree）

```
开始
│
├─ Q1: 一次通过率最高的是哪组？
│  ├─ A → "裸对话就够了" → 项目简单/探索期，别重配
│  ├─ B → "规则够用" → 增加技能库即可（省子智能体+Credits 开销）
│  └─ C → "全套最佳" → 继续看 Q2
│
├─ Q2: C 组 vs B 组的 Credits 差价 > 50%？
│  ├─ 是 → "配置太贵" → 用最小起步集（rules + skills，不加 subagents）
│  └─ 否 → "可承受" → 继续看 Q3
│
├─ Q3: 盈亏平衡点 ≤ 本项目预期任务数？
│  ├─ 是 → 采用 C 组全套（早配早赚）
│  └─ 否 → 推迟全配，先用最小起步集
│
└─ 决策输出:
   □ 轻量模式（A 组级别）
   □ 最小起步集（charter + 2 rules + 1 skill）
   □ 标准配置（B + skills）
   □ 全套 C 组（rules + skills + agents + hooks）
```

## 7. 局限性声明（Limitations）

本实验设计虽然控制了变量，但仍存在以下局限性:

1. **样本量 n=1**: 每组仅跑了一次，无法排除随机因素（如模型当天状态波动）
   - **缓解**: 对关键决策（如推广全套）建议至少复测一次

2. **任务选择偏差**: 统计报表页可能对规范资产"友好"（因为第 10-12 章都在强化它）
   - **缓解**: 换一个全新等价复杂度的任务重跑 A vs C 组

3. **模型依赖性**: 不同模型（GPT-4 vs Claude vs Gemini）对规则的遵循度可能差异巨大
   - **缓解**: 明确记录模型档位，推广时注明"适用于 XX 模型系列"

4. **人工审视主观性**: "一次通过率"的定义依赖人工判断是否存在"返工"
   - **缓解**: 制定客观判定标准（如 git diff 行数 > 0 即视为返工）
