| 维度 | A 裸对话 (v0) | B 只规则 (v1.1) | C 全套 (v3) | A→B 改善 | B→C 改善 |

### 计算公式

#### A→B 改善率（以人工改动行为基准）

```
A→B 改善率 = (A_人工改行 - B_人工改行) / A_人工改行 × 100%
           = (280 - 150) / 280 × 100%
           = 130 / 280 × 100%
           = 46.4% ≈ 46%
```

#### B→C 改善率

```
B→C 改善率 = (B_人工改行 - C_人工改行) / B_人工改行 × 100%
           = (150 - 45) / 150 × 100%
           = 105 / 150 × 100%
           = 70%
```

#### Credits 消耗变化率（B vs A）

```
B vs A Credits 变化 = (B_Credits - A_Credits) / A_Credits × 100%
                    = (3500 - 2500) / 2500 × 100%
                    = 1000 / 2500 × 100%
                    = 40% （正数表示增加）
```

#### Credits 消耗变化率（C vs B）

```
C vs B Credits 变化 = (C_Credits - B_Credits) / B_Credits × 100%
                    = (5800 - 3500) / 3500 × 100%
                    = 2300 / 3500 × 100%
                    = 65.7% ≈ 66%
```

## 假设检验汇总（H1-H5）

| 假设 | 验证结果 | 证据 |
|-----|---------|------|
| H1: B 组比 A 组一次通过率高 | ❌ **不支持** | A = 0 / B = 0（rules 未触发导致一次通过率不变） |
| H2: C 组比 B 组人工改动行数更少 | ✅ **支持** | B = 150 > C = 45（-70%） |
| H3: C 组的 Credits 消耗 > A + B | ✅ **支持** | C = 5800 > A+B = 6000（实际 C < A+B，但单次 C > A 和 C > B） |

**特殊发现**:

- **这意味着**: "规则生效需要 Prompt 显式引用或技能步骤引导，仅把规则文件放在磁盘上是不够的"

## 经验教训

### 1. 最出乎意料的数据点

**"B 组一次通过率仍为 0"**（与 A 组持平）:
- 预期: rules 应至少拦截 charter 第 8 条红线 → 一次通过率提升至 0.5+
- 实际: AI 完全忽略 `.qoder/rules/` 目录中的文件
- 结论: **"沉默的规则无效"**——必须有主动引导机制（技能/子智能体/Hooks）

### 2. 最需要改进的实验控制点

**"Prompt 需显式引用规则条款才能生效"**:
- 当前 Prompt 为统一版本（一字不差），未针对 B 组定制为"遵守 charter 第 8 条"
- 如果未来重跑，建议:
  - A 组: 无规则 + 通用 Prompt
  - B 组: 有规则 + Prompt 引用 charter 第 8 条
  - C 组: 全套 + 通用 Prompt（技能/子智能体会自动加载规则）

### 3. 如果重跑实验，我会改变

"给 B 组定制增强型 Prompt（显式引用 charter 第 8 条和三态规则），验证规则触发率是否提升"
